## Detailed Findings

### 🔴 CRITICAL ISSUES (Must Fix Before Merge)

#### 1. Missing `get_default_branch()` Method in BaseAdapter
**Severity:** CRITICAL (10/10)
**File:** `/Users/stephenbrandon/Dev/drep/drep/adapters/base.py`
**Impact:** Runtime errors when scanning Gitea repositories

**Issue:**
The `get_default_branch()` method is implemented in `GitHubAdapter` (line 183) but is NOT defined as an abstract method in `BaseAdapter`. This causes:

1. **GiteaAdapter doesn't implement it** → Runtime `AttributeError` when calling `adapter.get_default_branch(owner, repo)` on Gitea
2. **Interface inconsistency** → BaseAdapter contract is incomplete
3. **No compile-time safety** → Type checker can't catch missing implementations
4. **Future adapters will miss it** → GitLab adapter will likely forget this method

**Evidence from CLI code (drep/cli.py:202):**
```python
default_branch = await adapter.get_default_branch(owner, repo)
```

This calls the method on whatever adapter is selected (Gitea or GitHub), but Gitea doesn't have it.

**Fix Required:**
Add to `drep/adapters/base.py`:
```python
@abstractmethod
async def get_default_branch(self, owner: str, repo: str) -> str:
    """Get repository default branch name.

    Args:
        owner: Repository owner
        repo: Repository name

    Returns:
        Default branch name (e.g., "main", "master", "develop")

    Raises:
        ValueError: If repository not found or network/API error occurs
    """
    pass
```

And implement it in `GiteaAdapter`:
```python
async def get_default_branch(self, owner: str, repo: str) -> str:
    """Get repository default branch name."""
    url = f"{self.url}/api/v1/repos/{owner}/{repo}"

    try:
        response = await self.client.get(url)
        response.raise_for_status()
        data = response.json()

        if "default_branch" not in data:
            raise ValueError(
                f"Gitea API response missing 'default_branch' field for {owner}/{repo}"
            )

        return data["default_branch"]

    except httpx.HTTPStatusError as e:
        if e.response.status_code == 404:
            raise ValueError(f"Repository {owner}/{repo} not found")
        raise ValueError(f"Gitea API error: {e.response.text}")
```

**Testing Required:**
Add tests in `tests/unit/test_gitea_adapter.py`:
- `test_get_default_branch_success()`
- `test_get_default_branch_repository_not_found()`
- `test_get_default_branch_missing_field()`

**Priority:** Must fix before merge - this will break Gitea repository scanning.

### ⚠️ SECURITY CONCERNS

#### 2. Git Token Exposed in Environment Variables
**Severity:** MEDIUM (7/10)
**File:** `/Users/stephenbrandon/Dev/drep/drep/cli.py:190`
**Impact:** Token visible to process inspection, child processes, and system logs

**Issue:**
The git authentication token is passed via environment variable `DREP_GIT_TOKEN` to the askpass script. While the script file has restricted permissions (0o700), the environment variable is visible to:

1. Process tree inspection: `ps aux -e` shows environment variables
2. `/proc/<pid>/environ` on Linux (readable by same user)
3. Child processes inherit the environment
4. System audit logs may capture environment variables

**Evidence (drep/cli.py:176-180, 190):**
```python
askpass_content = """#!/bin/sh
if echo "$1" | grep -qi "username"; then
    echo "token"
elif echo "$1" | grep -qi "password"; then
    echo "$DREP_GIT_TOKEN"  # Token exposed in environment
fi
"""

# ... later ...
git_env = {"GIT_ASKPASS": str(askpass_script), "DREP_GIT_TOKEN": git_token}
```

**Recommendation:**
Use a temporary file with restricted permissions instead of environment variables:

```python
# Write token to temporary file with owner-only read permissions
token_file = Path(temp_dir) / ".git-token"
token_file.write_text(git_token)
token_file.chmod(0o600)

askpass_content = f"""#!/bin/sh
if echo "$1" | grep -qi "username"; then
    echo "token"
elif echo "$1" | grep -qi "password"; then
    cat {token_file}
fi
"""

# No DREP_GIT_TOKEN in environment
git_env = {"GIT_ASKPASS": str(askpass_script)}
```

This prevents token exposure in:
- Process listings (`ps aux -e`)
- System logs
- Child process environments

**Alternative Mitigation:**
If environment variable approach is kept, document this security tradeoff in CLAUDE.md and technical-design.md.

**Priority:** Should fix before production use, especially for CI/CD environments.

### 🟡 IMPORTANT IMPROVEMENTS (Should Fix)

#### 3. Inconsistent Constructor Parameter Order Across Adapters
**Severity:** MEDIUM (6/10)
**File:** `drep/adapters/github.py:49` vs `drep/adapters/gitea.py`
**Impact:** Maintenance burden, potential for bugs when adding new platforms

**Issue:**
Constructor parameter order differs between adapters:

- **GiteaAdapter:** `__init__(self, url: str, token: str)`
- **GitHubAdapter:** `__init__(self, token: str, url: str = "https://api.github.com")`

This inconsistency is documented in the docstring but creates confusion and risk when:
- Adding a third platform (GitLab) - which order to use?
- Refactoring code that creates adapters
- Reading code that instantiates different adapters

**Evidence from CLI (drep/cli.py:128 vs 136):**
```python
# Gitea: (url, token)
adapter = GiteaAdapter(config.gitea.url, config.gitea.token.get_secret_value())

# GitHub: (token, url) - DIFFERENT ORDER
adapter = GitHubAdapter(
    token=config.github.token.get_secret_value(),
    url=str(config.github.url) if config.github.url else "https://api.github.com",
)
```

**Recommendation:**
Standardize on `(url, token)` order for all adapters:

```python
# Option 1: Make GitHub match Gitea
class GitHubAdapter(BaseAdapter):
    def __init__(
        self,
        url: str = "https://api.github.com",
        token: str = None,  # Required despite default url
    ):
        if not token:
            raise ValueError("GitHub token is required")
        # ...
```

**OR** document this as an intentional design decision in CLAUDE.md:

```markdown
## Platform Adapter Constructor Convention

- **GiteaAdapter:** `(url, token)` - no defaults, both required
- **GitHubAdapter:** `(token, url)` - url has default (https://api.github.com)
- **Rationale:** GitHub.com is the common case, defaulting url improves DX
```

**Priority:** Medium - affects maintainability but not correctness.

#### 4. CLI Platform Detection Logic Duplicated
**Severity:** MEDIUM (6/10)
**File:** `drep/cli.py` (lines 119-155 and 373-396)
**Impact:** Code duplication, bug fixes must be applied twice

**Issue:**
The platform detection and adapter creation logic is duplicated between `_run_scan()` and `_run_review()` functions:

- Lines 119-155: Platform detection in scan command (37 lines)
- Lines 373-396: Identical logic in review command (24 lines)

This violates DRY principle and creates maintenance burden:
- Bug fixes must be applied in both places
- Adding a third platform requires updating both functions
- Inconsistency risk if one is updated without the other

**Recommendation:**
Extract to a factory function (as suggested by type-design-analyzer):

```python
@dataclass(frozen=True)
class PlatformContext:
    """Platform-specific configuration for repository operations."""
    platform_name: str  # "gitea" or "github"
    adapter: BaseAdapter
    git_url: str
    git_token: str

def create_platform_context(
    config: Config, owner: str, repo: str
) -> PlatformContext:
    """Create platform context from config, preferring Gitea."""
    if config.gitea is not None:
        adapter = GiteaAdapter(...)
        return PlatformContext("gitea", adapter, git_url, git_token)
    elif config.github is not None:
        adapter = GitHubAdapter(...)
        return PlatformContext("github", adapter, git_url, git_token)
    else:
        click.echo("Error: No platform configured...", err=True)
        raise click.Abort()

# Then in both _run_scan and _run_review:
platform_ctx = create_platform_context(config, owner, repo)
```

**Benefits:**
- Single source of truth for platform detection
- Easier to add GitLab support (one place to update)
- Type safety (`PlatformContext` guarantees all fields set together)
- Better testability (test factory independently)

**Priority:** Medium - consider for follow-up PR before adding GitLab.
