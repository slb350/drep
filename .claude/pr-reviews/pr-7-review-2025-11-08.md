#### 1. Git Operations - No Error Handling (Severity: CRITICAL)
**Location:** `drep/core/scanner.py:257-284` (`get_staged_files()`)
**Confidence:** 90/100

**Issue:** The `get_staged_files()` method performs git operations with ZERO error handling. Any git failure will crash with obscure GitPython exceptions.

**Code:**
```python
def get_staged_files(self, repo_path: str) -> List[str]:
    git_repo = Repo(repo_path)  # ❌ NO ERROR HANDLING
    staged_files = []

    for diff_item in git_repo.index.diff("HEAD"):  # ❌ FAILS ON INITIAL COMMIT
        path = diff_item.b_path
        if path and (path.endswith(".py") or path.endswith(".md")):
            staged_files.append(path)

    return staged_files
```

**Hidden Errors:**
1. `InvalidGitRepositoryError`: Not a git repository
2. `BadName`: No HEAD (initial commit scenario)
3. `GitCommandError`: Corrupted git index
4. `PermissionError`: Can't access `.git` directory

**User Impact:**
- Pre-commit hook crashes with cryptic error instead of helpful message
- **BLOCKS ALL COMMITS** with unhelpful traceback
- Users see "BadName: HEAD" instead of "Repository has no commits yet"

**Recommendation:**
```python
def get_staged_files(self, repo_path: str) -> List[str]:
    """Get staged files from git index (pre-commit workflow).

    Raises:
        ValueError: If repo_path is not a valid git repository
        RuntimeError: If git operations fail
    """
    from git.exc import InvalidGitRepositoryError, GitCommandError

    # Validate it's a git repository
    try:
        git_repo = Repo(repo_path)
    except InvalidGitRepositoryError:
        logger.error(f"Not a git repository: {repo_path}")
        raise ValueError(
            f"Not a git repository: {repo_path}\n"
            f"drep check --staged requires a git repository.\n"
            f"Try running 'git init' first or use 'drep check' without --staged."
        )

    # Get staged files, handling initial commit
    try:
        diff_items = git_repo.index.diff("HEAD")
    except GitCommandError as e:
        if "HEAD" in str(e):
            logger.warning(f"Repository has no commits yet")
            # Fallback for initial commit
            diff_items = git_repo.index.diff(None)
        else:
            raise RuntimeError(f"Git operation failed: {e}")

    staged_files = []
    for diff_item in diff_items:
        path = diff_item.b_path
        if path and (path.endswith(".py") or path.endswith(".md")):
            staged_files.append(path)

    return staged_files
```

**Missing Tests:**
- Test for non-git directory
- Test for initial commit (no HEAD)
- Test for corrupted git index

#### 2. Broad Exception Catching - Hides Errors (Severity: CRITICAL)
**Location:** `drep/cli.py:622-627` (`_run_check()`)
**Confidence:** 85/100

**Issue:** Config loading uses bare `except Exception` that catches **everything**, including KeyboardInterrupt and SystemExit.

**Code:**
```python
if config_path:
    try:
        config = load_config(config_path, require_platform=False)
    except Exception as e:  # ❌ TOO BROAD
        click.echo(f"Error loading config: {e}", err=True)
        raise SystemExit(1)
```

**Hidden Errors This Could Catch:**
- `KeyboardInterrupt`: User pressed Ctrl+C (should NOT be caught!)
- `SystemExit`: Another part trying to exit (recursion trap!)
- `ImportError`: Missing dependency (should crash to surface issue)
- `AttributeError`: Bug in load_config code (hides bugs!)

**User Impact:**
- User presses Ctrl+C but sees "Error loading config" instead of exiting cleanly
- Bugs in config loading show as config errors, not proper tracebacks
- Import errors for missing dependencies appear as config errors

**Recommendation:**
```python
if config_path:
    try:
        config = load_config(config_path, require_platform=False)
    except FileNotFoundError:
        click.echo(f"Error: Config file not found: {config_path}", err=True)
        raise SystemExit(1)
    except yaml.YAMLError as e:
        click.echo(f"Error: Invalid YAML in {config_path}\n{e}", err=True)
        raise SystemExit(1)
    except ValidationError as e:
        click.echo(f"Error: Configuration validation failed\n{e}", err=True)
        raise SystemExit(1)
    # DO NOT CATCH: KeyboardInterrupt, SystemExit, ImportError
```

**Missing Tests:**
- Test for malformed YAML
- Test for invalid LLM endpoint format
- Test that Ctrl+C works (doesn't hang)

#### 3. File Reading - Silent Errors (Severity: HIGH)
**Location:** `drep/core/scanner.py:345-352` and `431-438`
**Confidence:** 82/100

**Issue:** File reading errors are logged but execution continues. Error messages don't explain WHY or what to do.

**Code:**
```python
try:
    content = full_path.read_text(errors="ignore")  # ❌ HIDES ENCODING ERRORS
except Exception as e:  # ❌ TOO BROAD
    logger.error(f"Failed to read {file_path}: {e}")  # ❌ VAGUE MESSAGE
    tracker.update(failed=1)
    continue  # ❌ SILENTLY SKIPS FILE
```

**Hidden Errors:**
- `PermissionError`: User needs actionable fix ("run chmod +r")
- `UnicodeDecodeError`: Suppressed by `errors="ignore"`! Produces garbage for non-UTF8 files
- `FileNotFoundError`: Race condition (file deleted between listing and reading)

**User Impact:**
- User doesn't know WHY file couldn't be read
- Permission errors look identical to disk errors
- Non-UTF8 files analyzed as corrupted content (silent data corruption)

**Recommendation:**
```python
try:
    content = full_path.read_text(encoding="utf-8")  # DON'T USE errors="ignore"
except UnicodeDecodeError:
    logger.warning(f"Skipping {file_path}: Not valid UTF-8")
    click.echo(f"Warning: Skipping {file_path} (not UTF-8)", err=True)
    continue
except PermissionError:
    logger.error(f"Permission denied: {file_path}")
    click.echo(f"Error: Cannot read {file_path}: Permission denied\n"
               f"  Run 'chmod +r {file_path}' to fix", err=True)
    continue
except FileNotFoundError:
    logger.warning(f"File disappeared: {file_path}")
    continue
```

#### 4. Path Resolution - No Validation (Severity: HIGH)
**Location:** `drep/cli.py:641-656` (`_run_check()`)
**Confidence:** 85/100

**Issue:** The CLI resolves paths without validating they exist. Errors occur later with confusing messages.

**Code:**
```python
# Get files to check
path_obj = PathLib(path).resolve()  # ❌ NO VALIDATION

if staged:
    files = scanner.get_staged_files(str(path_obj))  # ❌ FAILS IF PATH INVALID
```

**User Impact:**
- User runs `drep check /nonexistent/path` and gets git errors, not "path not found"
- Error says "Not a git repository" when real issue is "path doesn't exist"

**Recommendation:**
```python
# Validate path exists
try:
    path_obj = PathLib(path).resolve(strict=True)  # strict=True raises if missing
except FileNotFoundError:
    click.echo(f"Error: Path not found: {path}", err=True)
    raise SystemExit(1)

# Additional validation for directory operations
if not path_obj.exists():
    click.echo(f"Error: Path does not exist: {path}", err=True)
    raise SystemExit(1)
```

**Missing Tests:**
- Test for nonexistent file path
- Test for nonexistent directory path

#### 6. Exit Code Stderr Confusion (Severity: MEDIUM)
**Location:** `drep/cli.py:593-600`
**Confidence:** 70/100

**Issue:** The `--exit-zero` flag still prints to stderr, which may confuse CI systems.

**Current:**
```python
if findings:
    click.echo(f"\n✗ Found {len(findings)} issue(s)", err=True)  # ALWAYS stderr
    if not exit_zero:
        raise SystemExit(1)
```

**Better:**
```python
if findings:
    if exit_zero:
        # Warning mode - print to stdout
        click.echo(f"\n⚠ Found {len(findings)} issue(s) (warning mode)")
    else:
        # Error mode - print to stderr
        click.echo(f"\n✗ Found {len(findings)} issue(s)", err=True)

    if not exit_zero:
        raise SystemExit(1)
```
